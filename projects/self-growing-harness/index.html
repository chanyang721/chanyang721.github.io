자가성장형 멀티에이전트 하네스

자가성장 가능한 개인용 멀티에이전트 하네스를 직접 만들고 운영하며, 에이전트의 한계 중 무엇이 엔지니어링으로 줄고 무엇이 환원 불가능한지를 실제 운영 데이터로 판단한 연구입니다. bash 기반 v1이 2026-06에 멈춘 뒤 2026-10부터 Herdr 터미널 앱 위에서 다시 만들어, Claude·Codex 세션 여러 개에 난이도별로 일을 나누고 작성자와 다른 계열 모델이 교차 검수하는 구조로 지금도 쓰고 있습니다.

Project Overview

"에이전트로 일하며 남는 판단을 어떻게 복리로 만들 것인가"에서 시작했습니다

AI로 일할 때마다 내리는 결정·시행착오·교훈이 세션이 끝나면 사라지고, 다음 작업에서 같은 실수를 반복하는 것이 출발 문제였습니다.

v1(2026-05~06)은 전략·구현·QA 같은 역할 에이전트를 macOS 터미널 분할 창에서 병렬로 돌리고, bash 라우터가 각 워커의 출력(outbox)을 집계해 지식 갭을 탐지하며, 기억·지식 서브시스템이 그 판단을 누적·distill해 다음 작업에 다시 주입하는 런타임이었습니다.

초기에는 메모리 시스템을 선언적으로만 도입해 실제 실행 시스템에 연결하지 않았고, 그 결과 거의 죽은 구조였습니다. 그래서 하네스를 기능을 쌓는 프레임워크가 아니라 판단을 반복 생산·구조화·재사용하는 runtime으로 재정의했고, 이 프로젝트는 그 과정에서 관찰한 에이전트의 구조적 한계를 정리한 연구 사례입니다.

지금 쓰는 구조(2026-10~)는 Herdr 터미널 앱 위에 있습니다. 프로젝트별 고정 작업 공간에 Claude·Codex 세션 여러 개가 열려 있고, 작업 배분 세션이 일마다 난이도 tier를 붙여 쉬는 세션에 보내거나 그 tier 모델로 새 세션을 엽니다. 작업 세션의 보고는 작성자와 다른 계열의 검수 세션이 판정하고, 과업·보고·판정·수락은 모두 고칠 수 없는 기록으로 남아 다음 세션의 문맥과 참고 사례로 다시 주입됩니다.

연구 성격

통제 벤치마크가 아니라, 실제 프로젝트에서 하네스를 돌리며 관찰한 자연 실험과 개입 전후 비교입니다. 이 방법 한계는 마지막에 그대로 명시합니다.

Ownership

직접 담당한 범위

  • 판단 휘발과 선언≠실행 단절을 문제로 정의하고, 레포를 "설정 모음"이 아니라 "판단을 누적하는 runtime"으로 재정의
  • 자가성장 루프를 탐지(코드 자동)와 변형(인간 게이트)으로 분리해 안전 경계를 명시
  • 실제 프로젝트 운영에서 관찰한 한계를 "줄임 / 환원불가"로 가르는 taxonomy로 구조화
  • 역할 복잡도·비용·효과를 기준으로 provider·모델 티어·추론 깊이(effort) 배분 정책을 설계
  • 설정한 모델 능력과 실제 적용 사이의 라우팅 gap("의도≠적용")을 코드에서 발견·문서화
  • v1이 멈춘 뒤 Herdr 위로 하네스를 다시 만들어, 작업 배분·교차 검수·수락·세션 정리를 고칠 수 없는 기록 위에서 판정하는 구조로 전환
  • 작업 난이도 tier와 남은 사용량으로 모델 계열·세션을 고르고, 작성자와 다른 계열이 검수하는 규칙을 코드로 고정
  • 학습 고리의 본선을 승인 관로에서 "검증 전 참고 사례 재사용 + 쓰인 결과로 걸러내기"로 전환

Constraints

먼저 해결해야 했던 제약

  • 통제 벤치마크(n>1, control)가 아니라 실제 운영 중 관찰이므로, 수치는 자연 실험·자체 측정치로만 제시해야 했습니다.
  • 모델 ID와 provider 정책은 시점 종속이라 관측 기준일을 명시해야 했습니다.
  • "자율 자가성장 AI"로 과장하지 않고, 변형이 인간 게이트로 막혀 있음을 그대로 드러내야 했습니다.
  • 시스템 규모(서브시스템 수·역할 수)를 성과처럼 나열하지 않고, 한계 발견을 중심에 두어야 했습니다.
  • 두 컴퓨터(Windows·macOS)에서 여러 세션이 동시에 돌기 때문에, 실행 중인 세션을 끊지 않고 하네스를 갱신하고 기록이 서로 충돌하지 않아야 했습니다.
  • 한 모델 계열의 사용량이 떨어지면 교차 검수가 멈출 수 있어, 같은 계열 대체 검수를 수락 근거로 쓰지 않는 규칙이 필요했습니다.

Implementation Timeline

연구를 다섯 축으로 나눠, 자가성장 설계부터 Herdr 기반 재구축까지 살펴봅니다

자가성장 하네스를 만들며 관찰한 것을 다섯 축으로 나눴습니다: 안전 경계 설계, 모델 능력 배분, 실제로 만든 검증 산출물, 그 위에서 갈라낸 한계, 그리고 v1이 멈춘 뒤의 Herdr 기반 재구축. 앞의 네 축은 v1에서 나온 관찰이고, 다섯 번째 축은 그 판단을 이어받아 다시 만든 현재 구조입니다. 필요한 Phase를 선택하면 해당 단계에서 어떤 문제를 보고 어떤 구조와 검증 기준으로 이어졌는지 확인할 수 있습니다.

Phase 01 · 탐지·변형 분리 설계

탐지·변형 분리 설계

Phase 01 · Self-Growth Loop

탐지는 코드로 자동화하고, 변형은 인간 게이트로 막았습니다

자가성장을 "탐지"와 "변형"으로 분리한 것이 안전 경계의 핵심입니다. 탐지는 자동화하되, 기억을 실제로 바꾸는 변형은 사람 비준을 통과해야만 합니다.

  1. 01

    탐지는 코드로 자동화

    워커가 outbox에 [KNOWLEDGE_GAP] 같은 마커를 남기면 router가 카운터를 올리고, clo-trigger-check가 임계값(K3=3, K4=5)을 넘는지 스캔해 CLO inbox에 자동 기록합니다.

  2. 02

    변형은 사람이 비준

    기억(brain)을 실제로 바꾸는 변형은 CLO consolidation + 사람 비준 + sentinel을 통과해야만 허용됩니다. sentinel이 없으면 PreToolUse hook이 편집 자체를 차단합니다.

  3. 03

    경계를 이렇게 가른 이유

    기억을 자동으로 덮어쓰면 잘못된 학습이 조용히 누적되고, 자기참조 거버넌스의 검증 실패를 사람이 못 잡습니다. 그래서 탐지=코드, 변형=인간 게이트로 성숙도 경계를 고정했습니다.

변형을 자율화하지 않는다

선택

탐지·에스컬레이션까지만 코드로 자동화하고, brain 변형은 CLO consolidation + 사람 비준 + sentinel을 통과해야만 허용했습니다.

문제
탐지 신호가 임계값을 넘으면 시스템이 자동으로 개선 후보를 만들 수 있습니다.
이유
기억을 자동으로 덮어쓰면 잘못된 학습이 조용히 누적되고, 자기참조 거버넌스의 검증 실패를 사람이 못 잡습니다.
방어 장치
  • PreToolUse hook이 sentinel 없는 brain 편집을 차단
  • 변형은 append 우선, 무단 삭제 금지

Trade-off완전 자율 대비 사람이 병목이지만, 안전한 성숙도 경계를 명확히 유지합니다.

정직한 성숙도

탐지는 자동이지만 변형은 의도적으로 비자율입니다. "자율 자가성장 AI"라고 부르지 않습니다.

Development History

2026-06에 한 번 멈췄고, 2026-10 Herdr 위에서 다시 만들어 지금도 운영 중입니다

방향은 여러 소스에 나뉘어 기록됐습니다. v1의 창립 결정은 git 이전 ADR·CHARTER에, 견고화는 2026-05 말~06 초 커밋에 남아 있고, v1은 2026-06 중순 이후 멈췄습니다. 2026-10 말부터의 Herdr 기반 재구축은 재구축 레포와 원래 레포의 ADR·운영 문서·작업 기록에 남아 있습니다.

v1의 git 히스토리는 창립기가 아니라 운영 하드닝 스프린트입니다. 창립 작업(ADR-0008 메모리 배선, CHARTER의 runtime 재정의)은 git 이전에 이뤄졌고, 커밋에서 시작일을 끌어오면 왜곡됩니다. 그래서 창립은 ADR·CHARTER에서, 페이즈별 견고화는 커밋에서 각각 인용합니다.

현재 구조는 2026-11에 커밋이 몰린 짧고 밀도 높은 구간에서 만들어졌습니다. 커밋 수를 성과로 쓰지 않고, 무엇을 왜 바꿨는지를 ADR과 결정 기록 수준으로만 인용합니다.

정직한 프레이밍

v1의 git 창은 짧은 하드닝 구간이고, 현재 구조는 2026-11에 몰린 짧고 밀도 높은 구간에서 만들어졌습니다. 둘 다 "몇 달 개발"로 읽으면 안 되며, 지속 기간보다 무엇을 왜 바꿨는지가 근거입니다.

Outcome

확인 가능한 결과

  • 에이전트 한계를 "줄임 / 환원불가"로 가르는 실사용 taxonomy(줄임 2 / 부분 1 / 환원불가 2)
  • Bootstrap Paradox — 자기참조 거버넌스에는 환원 불가능한 human-in-the-loop 바닥이 있음을 확인
  • 판단=claude·병렬성 / 실행=codex·모델 깊이로 나누는 모델 능력 배분 정책 도출
  • "의도≠적용" gap — 라우팅 구조가 설정한 모델 능력을 무효화할 수 있음을 코드에서 발견
  • 자가성장의 정직한 경계선(탐지=자동, 변형=인간게이트)을 과장 없이 표현
  • 현재 구조 — 작성자와 다른 계열 모델이 검수하고 그 판정을 집계해 수락하는 교차 검수 흐름을 코드로 고정
  • 현재 구조 — 과업·보고·판정·수락을 고칠 수 없는 기록으로 남겨, 세션 정리와 학습을 같은 기록 위에서 판정
  • 현재 구조 — 학습 고리를 "검증 전 사례 재사용 + 쓰인 결과로 걸러내기"로 전환(기본 꺼짐, 효과 측정 전)

Limitations

한계와 미구현 범위

  • n=1 자기보고 연구입니다. 통제군이 없고 관찰자가 운영자 본인이므로 일반화에는 한계가 있습니다.
  • 작동률 15%→60%, 토큰 71%↓, 29개 중 5개 같은 수치는 통제 eval이 아니라 운영 중 관측·자체 측정치입니다.
  • 모델 ID(Opus/Sonnet/Haiku)와 provider 정책은 2026-06 기준이고, 현재 구조의 tier별 모델 매핑도 시점 종속입니다. 모델 세대가 바뀌면 배분 판단도 달라집니다.
  • v1 서브시스템 다수(거버넌스·지식 분배 층)는 새 구조에 아직 연결되지 않았고, import 게이트 실효성 검증도 진행하지 않았습니다.
  • 교차 검수가 실제로 잡은 결함 수와 정리 지연 변화는 집계하지 않았습니다. 한 모델 계열의 사용량이 떨어지면 독립 검수가 멈춥니다.
  • 사례 재사용 학습은 기본 꺼짐이고, 쓰인 결과는 세션의 자기 보고라 효과는 아직 측정 전입니다.
Confidentiality

v1은 근거 원천이 본인 개인 레포라 고용주 기밀 리스크가 없어 함수명·라인·커밋 해시까지 공개합니다. 현재 구조는 설계 판단과 한계 수준으로만 적고, 레포 주소·명령·설정·세션 기록·운영 기록은 공개하지 않습니다. 개인 판단 기억(brain) 원문과 진행 중 미검증 수치도 공개하지 않습니다.
