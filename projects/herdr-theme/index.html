Project Overview

여러 코딩 에이전트를 터미널에 띄워 둘 때 “누가 무엇을 하고 있는가”를 한 화면에서 보려는 데서 시작했습니다

Claude Code·Codex 같은 에이전트를 Herdr 칸마다 띄우면, 어느 칸이 일하는 중이고 어느 칸이 사람의 답을 기다리는지, 다른 컴퓨터와 어떤 메시지가 오가는지, 요금제 한도가 얼마나 남았는지가 흩어져 보입니다.

herdr-theme는 이 정보를 한 사이드바와 칸 머리줄에 모은 Herdr용 레이아웃·테마입니다. 컴퓨터별 에이전트 수와 공유 프로젝트, 안 읽은 메시지와 메시지 경로 애니메이션, 칸별 모델·추론 깊이·세션 사용량, CPU/RAM·MCP 연결·CLI 로그인·요금제 한도, 프로젝트 문서 검색과 문서 탭을 제공합니다.

화면은 JavaScript mod로, 설치·갱신·문서·수집·음성 같은 도우미는 Rust 실행 파일 herdr-theme로 나눴습니다. 작업 배정·수락·정리 같은 판단은 테마가 하지 않고, 선택적으로 붙는 외부 생산자가 쓰는 로컬 피드 파일을 읽어 표시만 합니다.

공개 화면 자료의 성격

README의 워크플로 GIF와 기능 갤러리는 합성 데이터로 만든 네이티브 캡처를 편집한 것이며, 실제 작업이 자동으로 끝까지 진행된 녹화가 아닙니다. 저장소도 같은 내용을 명시합니다.

Ownership

직접 담당한 범위

  • Herdr 앱 위에서 동작하는 사이드바·칸 머리줄·모니터 띠 mod와 레이아웃·색 테마를 설계하고 구현
  • 화면이 작업 상태를 추측하지 않도록, 외부 생산자가 쓰는 버전 있는 피드와 표시 전용 수명주기 계약·JSON 스키마를 정의
  • 질문·권한 카드의 버튼을 요청 파일, 설정된 명령, 수신 확인(receipt)으로만 넘기는 로컬 연동 확장 지점 설계
  • Python 도우미 97개 파일을 원래 출력 고정본과 원본 시험 대응표를 기준으로 Rust 실행 파일 herdr-theme로 이식
  • 음성 받아쓰기에 주변 사람 말이 섞여 전송되는 경로를 분석하고 전송 시점 검사 hook으로 차단
  • mod 타이머를 정적으로 검사하는 CPU 가드 시험과 Ubuntu·Windows·macOS CI 매트릭스 구성

Constraints

먼저 해결해야 했던 제약

  • Herdr는 업스트림 오픈소스 앱이라, 테마는 앱·코어를 고치지 않고 mod·레이아웃·외부 실행 파일 범위 안에서만 동작해야 했습니다.
  • 메시지 애니메이션에 필요한 코어 이벤트는 업스트림에 제안한 PR이 아직 열려 있어, 표준 릴리스가 그 이벤트를 낸다고 가정할 수 없었습니다.
  • 공개 저장소이므로 기기별 경로·계정·개인 설정을 코드와 화면 자료에 남기지 않고, git이 무시하는 *.local.json으로 분리해야 했습니다.
  • 사이드바 mod의 주기 타이머와 폴링이 늘면 창을 띄워 둔 것만으로 CPU를 쓰게 되므로, 타이머 하나하나를 결정으로 다뤄야 했습니다.
  • macOS·Windows·Linux의 빌드 도구, 오디오, 렌더링 환경이 달라 검증 범위를 플랫폼별로 나눠 적어야 했습니다.

Implementation Timeline

표시 경계, 음성 안전장치, 네이티브 이식, 연동 경계, CPU 비용 순으로 살펴봅니다

공개 저장소의 PR·문서·시험을 기준으로 설계 판단이 드러나는 다섯 갈래를 골랐습니다. 순서는 처음 다룬 시점 기준이며, 각 갈래는 지금도 함께 고쳐지고 있습니다. 필요한 Phase를 선택하면 해당 단계에서 어떤 문제를 보고 어떤 구조와 검증 기준으로 이어졌는지 확인할 수 있습니다.

Phase 01

응답이 끝났다는 사실을 “작업 완료”로 보이지 않게 했습니다

사이드바는 배정·작업·검수·수락·보관·정리를 보여 줍니다. 화면이 진행률이나 응답 종료로 상태를 추측하면, 남은 일이 있는 작업도 완료처럼 보이고 아직 열린 칸이 닫힌 것처럼 사라질 수 있습니다.

재생 단계와의 연결재생의 상태·정리 장면을 받치는 결정입니다. 행의 단계 칸과 상태 아이콘, 정리 4단계는 이 계약의 값을 그대로 그린 것입니다.02 작업 4단계와 상태08 정리

테마는 피드의 작업 단계(stage 0–5)와 칸의 관찰 상태(status·state)를 따로 받아 그립니다. 일하는 중, 대기, 사람 필요, 결과 미확인, 정리 대기, 닫는 중, 닫힘을 서로 다른 상태로 두고, 이슈 번호·역할 이름·진행률·경과 시간으로 새 상태를 만들지 않습니다. 행을 지우는 것은 생산자가 닫기 4단계를 확인했을 때뿐이며, state: closed 하나만으로는 지우지 않습니다.

피드는 최대 2 MiB만 읽고 ready·missing·invalid로 보고합니다. 쓰기 중단이나 읽기 실패는 마지막 정상 화면을 유지하고, 피드 안에 들어 있는 명령은 실행하지 않습니다. 화면 이동도 피드가 명시한 공간·칸 대상으로만 하며, 불투명 ID로 대상을 추측하지 않습니다.

상태를 추론하지 않고 생산자의 증거를 그대로 표시

선택

작업 단계와 칸 상태를 독립 필드로 받고, 행 제거는 생산자가 확인한 닫기 4단계에만 묶었습니다. 수락된 작업이라도 칸이 남아 있으면 행을 유지합니다.

문제
응답 종료, 꽉 찬 진행 막대, 보낸 메시지, 만료된 카운트다운은 실제 수락이나 정리의 증거가 아니었습니다.
이유
화면이 틀린 추측을 하면 사용자는 남은 일을 놓칩니다. 판단 책임을 증거를 가진 쪽에 두면 테마는 어떤 생산자와 붙어도 같은 의미로 동작합니다.

Trade-off피드가 없으면 작업 트리는 보이지 않고 기본 사이드바만 남습니다. 생산자가 갱신하지 않으면 오래된 행이 남을 수 있어 갱신 책임이 생산자에게 갑니다.

Outcome

확인 가능한 결과

  • Herdr 0.1.11 이상에서 동작하는 사이드바·칸 머리줄·모니터 띠·문서 탭 레이아웃을 Apache-2.0 공개 저장소로 배포하고, 기존 설정을 보존하는 Rust 설치·갱신 명령 제공
  • 작업 단계·칸 상태·닫기 단계를 분리한 표시 전용 피드 계약과 JSON 스키마, 7가지 칸 상태 표시 구현
  • Python 도우미 97개 파일을 제거하고 Rust 실행 파일 하나로 대체하면서 파일별 대응표와 원래 출력 고정본을 회귀 기준으로 유지
  • 전송 시점 검사 hook과 헤드셋 전용 자동 전송으로 판정 근거가 없는 음성 받아쓰기 전송 차단(macOS)
  • mod 타이머 정적 검사와 4개 러너 CI로 CPU 비용 구조와 플랫폼별 회귀를 자동 검사

Limitations

한계와 미구현 범위

  • 메시지 애니메이션에 쓰는 코어 이벤트는 업스트림 PR(herdr-core #167)이 2026-11-24 기준 열려 있어, 표준 릴리스에서는 호환 어댑터나 로컬 수집기가 따로 필요합니다.
  • Linux는 네이티브 도우미만 지원하고 데스크톱 UI는 검증하지 않았습니다. 음성과 HTML 스냅샷은 macOS 전용입니다.
  • README의 워크플로 GIF와 갤러리는 합성 데이터 캡처를 편집한 것이며 실제 종단 작업 녹화가 아닙니다. 주간 타임라인 기능은 새 네이티브 캡처가 아직 없습니다.
  • 작업 트리·카드·보고는 외부 생산자를 따로 구성해야 나타나며, 테마 설치에는 작업 서비스가 포함되지 않습니다.
  • 화자 판정 수치는 공개 음성과 합성 조건의 오프라인 평가이며 실사용 정확도가 아닙니다.
  • 큰 수명주기·설치 모듈과 도메인별 IO 파사드는 리팩터링 대상 구조 부채로 남아 있고, CPU 변경 전후 사용량은 측정 기록이 없습니다.
