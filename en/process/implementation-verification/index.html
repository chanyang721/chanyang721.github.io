Process Evidence · 04

Connect the design to use cases, contracts, and code verification

I formalized domain models as actual APIs, DTOs, sequence diagrams, and server-side revalidation criteria.

I separated use cases such as previews, orders, payment initiation, authorization checks, callbacks, and status queries, and documented verification conditions for each stage.

How I worked

Actual Working Approach

  1. Input

    I reviewed user scenarios, gateway return and callback flows, responses needed by the frontend, and states operators needed to inspect as one flow.

  2. Questions to ask

    I identified the use case each API completes, which values are hints versus values the server must recalculate, and which states define acceptance criteria.

  3. Output

    I kept sequence diagrams, DTOs, endpoint order, error responses, unimplemented scope, and server-side revalidation conditions in the same document.

Detailed work example

Connecting verification, approval, and rejection flows to API contracts and test units

In the private B2B platform, I sought to connect company-verification requests, employee-verification approvals and rejections, and vendor-category approvals to controllers, services, repositories, factories, DTOs, Swagger documentation, and tests. A later code audit separated passing builds from runtime-contract verification, documenting gaps in verification criteria rather than claiming success.
