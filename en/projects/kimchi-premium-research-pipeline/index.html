Ownership

My direct responsibilities

  • Documented the threshold-strategy hypothesis and experimental procedure based on fluctuations in the kimchi premium
  • Cleaned hourly exchange-rate, BTC, and USDT price data for 2021–2024 and verified the kimchi premium (KPR) formula
  • Calculated profit and loss for buy/sell threshold combinations, generated heatmaps, and compared risk-adjusted returns, gain-to-loss ratios, and buy-and-hold performance
  • Automated hourly price updates using Yahoo Finance and Bithumb data, with uploads to Google Drive
  • Implemented an Excel-based trading log structure separating funds, wallets, orders, and executions by strategy

Constraints

Constraints to address first

  • Even for the same strategy, favorable thresholds varied by validation period, so a single result could not be generalized.
  • I needed to align time zones and missing intervals in the price data and compare the results of the existing kimchi premium formula with a simplified formula.
  • Backtest returns could differ from actual execution results because of fees, slippage, liquidity, and partial fills.
  • The project was halted before live order automation was complete, so research and prototype work had to be distinguished from operational outcomes.

Phase 01 · Threshold Backtesting

Threshold Backtesting

Phase 01

I selected threshold candidates through simulated trading and passed them on as strategy configuration values

The rules bought USDT when the kimchi premium crossed below a lower threshold and sold when it crossed above an upper threshold. I varied buy/sell thresholds in increments of 0.5 and calculated results with a 0.2% trading fee.

  1. 01

    Data Alignment

    I aligned the hourly USD/KRW, BTC/USDT, and BTC/KRW data and filled missing weekend intervals to build the 2021–2024 validation dataset.

  2. 02

    Combination Search

    I ran only combinations with a buy threshold below the sell threshold, calculated trade counts and cumulative profit and loss for each, and compared them in heatmaps.

  3. 03

    Result Comparison

    I updated simulated KRW and USDT balances and portfolio values at each time point to calculate per-trade and cumulative profit and loss, then compared risk-adjusted returns, gain-to-loss ratios, and buy-and-hold returns.

Values Passed to the Next Phase and Limits of Interpretation

I passed the short- and long-term buy/sell thresholds reviewed in the heatmaps into the Strategy A/B configuration. However, the 2024 condition-selection period overlaps with the 2021–2024 revalidation period, so this is not independent validation using fully separate periods. I do not present any specific return or optimal value as a headline outcome.

Outcome

Verifiable outcomes

  • Implemented a backtest calculating profit and loss and comparison metrics for threshold combinations using hourly price data
  • Created result reports with return heatmaps and buy-and-hold comparisons to review strategy conditions
  • Automated hourly price collection, merging with existing data, and loading to local storage and Google Drive
  • Implemented per-strategy wallet, fund, order, and execution log schemas and exchange-response mapping

Limitations

Limitations and unimplemented scope

  • This was not independent validation with fully separate backtest and strategy-condition selection periods.
  • Some threshold values differ between the documentation and experiment artifacts, so I do not present an exact optimum as a headline outcome.
  • Live order automation and recovery from partial fills and exchange failures remained incomplete because the project was halted.
  • Update status was checked every hour, but gaps in exchange-rate data availability were not automatically filled.
  • Backtest returns should not be interpreted as actual investment performance or risk-free arbitrage results.
